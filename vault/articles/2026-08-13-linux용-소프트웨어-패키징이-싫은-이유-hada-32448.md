## GeekNews 요약
- 터미널 편집기 **Fresh**를 모든 Linux 사용자가 쉽게 설치할 수 있도록 여러 배포 채널을 지원했지만, 채널이 늘어날수록 릴리스 유지 비용과 장애 가능성도 커짐
- npm, Cargo, AppImage, Flatpak, deb, rpm, AUR, Nix, mise 등은 각기 일부 사용자에게만 적합하며 **보안·호환성·샌드박스·업데이트** 문제가 서로 다름
- AppImage는 시작이 느리고, Flatpak은 시스템과 네트워크에 폭넓게 접근하는 TUI에 맞지 않으며, deb와 rpm은 공식 저장소 밖에서는 시스템 업데이트로 새 버전을 받기 어려움
- 오래된 배포판의 **libc 호환성**, Debian의 Rust 의존성 정책, mise의 신뢰 루트 장애, AUR의 읽기 전용 전환처럼 개발자가 통제할 수 없는 문제까지 관리해야 함
- 앞으로는 약 12MB인 **정적 musl 바이너리**와 사용자가 직접 실행하는 자체 업데이트 기능을 Linux의 권장 배포 방식으로 삼고, 기존 패키지와 소스 빌드도 당분간 유지함
