## GeekNews 요약
- Zig는 `build.zig`와 빌드 시스템을 별도 프로세스로 분리한 흐름에 맞춰, **패키지 관리 로직**을 컴파일러 실행 파일 밖의 maker 프로세스로 옮김
- `zig build`, `zig fetch`, `zig init`, `zig libc`가 maker 쪽으로 이동하면서 HTTP, TLS, Git, 압축, `build.zig.zon` 처리 코드가 **소스 형태**로 배포됨
- 이 구조에서는 컴파일러 재빌드 없이 패키지 관리 기능을 고칠 수 있고, maker가 `ReleaseSafe`로 컴파일되어 네트워킹 작업의 **안전성 검사**도 활성화됨
- 원래 목적은 build server protocol을 노출해 ZLS를 막고 있던 `--build-runner` 변경 문제를 푸는 것이며, 새 프로세스 트리에서는 maker가 configurer의 부모로 남아 설정 재실행을 더 안정적으로 처리할 수 있음
- 사용자 영향은 크지 않지만 Zig 실행 파일은 14.1MiB에서 13.5MiB로 4% 줄고, `--maker-opt`와 `--zig-lib-dir`는 각각 `ZIG_DEBUG_MAKER`, `ZIG_LIB_DIR` 환경 변수로 대체됨
