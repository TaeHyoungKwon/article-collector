## GeekNews 요약
- Rust와 C/C++의 CVE 숫자를 그대로 비교하면, **메모리 안전성 취약점**을 “라이브러리 문제”로 보는 기준 차이를 놓치기 쉬움
- C/C++에서는 잘못된 API 호출로 UB나 세그폴트가 나도 대개 **사용자 코드의 오용**으로 처리되며, 가능성 자체를 전부 CVE로 등록하지 않음
- `libcurl`의 `curl_getenv(NULL)` 호출은 경고 없이 빌드되고 실행 시 세그폴트가 날 수 있지만, 보통 `curl` 취약점으로 보지는 않음
- Rust에서는 사용자 코드에 `unsafe`가 없는데 안전한 API 호출만으로 메모리 버그가 발생하면, 라이브러리의 **soundness bug**로 간주함
- 그래서 Rust의 일부 CVE는 C/C++보다 더 엄격한 기준으로 기록되며, **원시 CVE 수 비교**만으로 메모리 안전성을 판단하기 어려움
